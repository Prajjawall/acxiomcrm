# User and Role Administration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans if your harness has them; otherwise execute task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Admin-only user management (create, edit, role, manager, activate/deactivate, unlock, reset password) and a read-only Roles/Permissions page, with safety guards and audit.

**Architecture:** `IUserAdminService` (Application contract, Infrastructure implementation over `UserManager`). All security-sensitive changes bump the security stamp so sessions end within the validation interval. Roles page renders `RolePermissionMap`.

**Tech Stack:** ASP.NET Core Identity `UserManager`, Razor, xUnit, Playwright.

**Spec:** PRD USR-01..07, AUTH-05/06/10, AUTHZ-05, D-08, D-09, D-23; SECURITY-AUTHZ §2, §4.

**Depends on:** Plan 08 (Part B) and plans 04–07 (reassignment touches their entities).

## Global Constraints
- Only `users.manage` may create/edit/role-change/activate/deactivate; `users.unlock` unlock; `users.resetpassword` reset. Manager has `users.view` (team, read-only) only when `Users:ManagerCanViewTeam=true` (default true).
- Exactly one role per user: `Admin | Manager | SalesExecutive`. `ManagerId` is only valid for `SalesExecutive` and must reference an **active Manager**.
- Guards: an Admin cannot deactivate or demote themselves; the **last active Admin** can never be deactivated or demoted (`At least one active administrator is required.`).
- Temporary password: generated server-side (≥ 16 chars, policy-compliant, CSPRNG), shown **once** on the result page (never stored plain, never logged/audited), sets `MustChangePassword=true`, bumps security stamp, clears lockout.
- Never expose hash/stamp/tokens in views, DTOs, logs, audit. `UserListItem`/`UserDetail` have no such fields.
- Deactivation requires choosing a reassignment target for the user's open work or leaving it flagged (USR-07): open leads (not Converted/Lost), open opportunities, planned follow-ups, planned activities.
- Audit actions: `Create`, `Update`, `RoleChanged` (old/new role), `Activated`, `Deactivated`, `Unlock`, `PasswordReset` (no secret), `Assigned` for bulk reassignment (count in details).

## Review Focus
- Admin A demotes Admin B while B is the only other Admin → allowed; demoting the last remaining Admin → blocked, also under concurrency (two admins demoting each other at the same time → one fails).
- Role changed Manager → SalesExecutive for a manager who has direct reports: reports are left with `ManagerId` pointing to a non-manager → blocked unless team reassigned: `Reassign this manager's team first.`
- Setting `ManagerId` to a user who is a SalesExecutive, deactivated, or the user themselves → rejected.
- Deactivated user's active session/cookie/JWT stops working within the validation interval (stamp) and API refresh tokens are revoked immediately.
- Username/email change to an existing one → field error; email normalisation case-insensitive.
- Reset password on a locked user also unlocks; resetting for the bootstrap admin allowed only by another Admin or self via change-password flow.
- A Manager crafting a POST to `/Users/Create` → 403; GET list for another team's user id → 404.
- Reassignment target in another team or inactive → rejected; reassignment is atomic (all or nothing).

**Interfaces:**
- Produces:
```csharp
public sealed record UserFilter(string? Search = null, string? Role = null, bool? Active = null, bool? LockedOut = null, string? ManagerId = null);
public sealed record UserListItem(string Id, string FullName, string UserName, string Email, string Role, bool IsActive, bool LockedOut, DateTime? LockoutEndUtc,
    string? ManagerId, string? ManagerName, DateTime? LastLoginDateUtc, DateTime CreatedDate);
public sealed record UserDetail(string Id, string FullName, string UserName, string Email, string Role, bool IsActive, bool LockedOut, DateTime? LockoutEndUtc,
    string? ManagerId, string? ManagerName, bool MustChangePassword, DateTime? LastLoginDateUtc, DateTime CreatedDate, int OpenLeads, int OpenOpportunities, int PlannedFollowUps);
public sealed record CreateUserCommand(string FullName, string UserName, string Email, string Role, string? ManagerId, bool IsActive);
public sealed record UpdateUserCommand(string FullName, string UserName, string Email, string Role, string? ManagerId);
public sealed record DeactivateUserCommand(string? ReassignToUserId);      // null = leave flagged
public sealed record CreatedUserResult(string UserId, string TemporaryPassword);   // shown once
public interface IUserAdminService {
    Task<PagedResult<UserListItem>> SearchAsync(UserFilter f, PageQuery p, CancellationToken ct = default);
    Task<Result<UserDetail>> GetAsync(string id, CancellationToken ct = default);
    Task<Result<CreatedUserResult>> CreateAsync(CreateUserCommand c, CancellationToken ct = default);
    Task<Result<UserDetail>> UpdateAsync(string id, UpdateUserCommand c, CancellationToken ct = default);          // handles role change + guards
    Task<Result> ActivateAsync(string id, CancellationToken ct = default);
    Task<Result> DeactivateAsync(string id, DeactivateUserCommand c, CancellationToken ct = default);
    Task<Result> UnlockAsync(string id, CancellationToken ct = default);
    Task<Result<string>> ResetPasswordAsync(string id, CancellationToken ct = default);                            // returns the temporary password once
    Task<IReadOnlyList<RoleSummary>> GetRolesAsync(CancellationToken ct = default);                                // name, member count, permissions
}
public sealed record RoleSummary(string Name, string DisplayName, int MemberCount, IReadOnlyList<string> Permissions);
```
