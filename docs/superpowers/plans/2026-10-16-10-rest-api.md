# REST API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans if your harness has them; otherwise execute task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A secured, documented REST API for auth, customers, leads, opportunities, follow-ups, activities and pipeline reporting, built on the same services as the MVC app.

**Architecture:** `Controllers/Api/*` are thin adapters over the Application services. A policy authentication scheme selects JWT Bearer or the Identity cookie. Refresh tokens are rotating and stored hashed. Errors are RFC 7807. OpenAPI is generated and snapshot-tested.

**Tech Stack:** `Microsoft.AspNetCore.Authentication.JwtBearer`, built-in OpenAPI (.NET 10) or Swashbuckle, xUnit, `WebApplicationFactory`.

**Spec:** `docs/api/API-SPEC.md` (entire), PRD API-01..08, AUTH-11, D-22; SECURITY-AUTHZ §4.

**Depends on:** Plans 04–08 (services), 02.

## Global Constraints
- Paths, verbs, status codes, DTO names and field names exactly as API-SPEC. JSON camelCase, enums as strings, `Content-Type: application/json` required on bodies else 415.
- Access token 15 min, refresh 7 days (config), rotating; reuse of a rotated token revokes the chain and audits `RefreshReuseDetected` (module Security).
- Response bodies never contain `passwordHash`, `securityStamp`, `rowVersion`, `isDeleted`, `emailNormalized`, `concurrencyStamp`.
- Cookie-authenticated unsafe API calls require `X-CSRF-TOKEN`; Bearer calls don't.
- Rate limit `auth` policy on `/api/auth/*` (429 + `Retry-After`).
- 500 → problem+json with `traceId` only. No stack traces. Unknown routes under `/api` → problem+json 404, not HTML.
- Swagger UI: Development always; Production only for Admin; never anonymous.

## Review Focus
- Token with valid signature but user now inactive/role changed (stamp mismatch) → 401 on the next call (stamp claim check).
- `alg=none`, wrong audience/issuer, expired by 31 s, token signed with a different key → 401.
- `PUT` without `If-Match` → 428; stale → 409; wildcard `*` accepted only if the resource exists.
- `GET /api/customers?pageSize=100000&page=-4&sort=passwordHash` → clamped paging; unknown sort key ignored (default sort), never an error exposing columns.
- Out-of-scope id on `GET/PUT/DELETE/POST …/status` → 404 identical body to a non-existent id (no timing/shape difference).
- Mass assignment: JSON body with `ownerId` as an executive, `status:"Converted"`, `isDeleted:true`, `id:999`, `rowVersion` → ignored or rejected, never applied.
- Large body (>1 MB) → 413; malformed JSON → 400 problem with no parser internals; wrong enum string → 400 naming the field.
- Login for a locked account returns 423 with `retryAfterSeconds`, and identical timing/shape for unknown vs wrong-password (401 generic).
- `OPTIONS`/CORS: no CORS enabled by default; a test asserts no `Access-Control-Allow-Origin` header on any response.

- Test: `tests/AcxiomCrm.Infrastructure.Tests/{TokenServiceTests,RefreshTokenConstraintTests}.cs`, `tests/AcxiomCrm.Web.Tests/{AuthApiTests,JwtValidationTests,AuthSchemeSelectionTests}.cs`

**Interfaces:**
- Produces:
```csharp
public sealed record TokenPair(string AccessToken, int ExpiresInSeconds, string RefreshToken);
public interface ITokenService {
    Task<TokenPair> IssueAsync(string userId, string? ip, CancellationToken ct = default);
    Task<Result<TokenPair>> RefreshAsync(string refreshToken, string? ip, CancellationToken ct = default);   // rotates; reuse → revoke chain + audit
    Task RevokeAsync(string refreshToken, CancellationToken ct = default);
}
public interface IRefreshTokenRevoker { Task RevokeAllAsync(string userId, CancellationToken ct = default); }
```
- Access token claims: `sub` (user id), `name`, `role`, `jti`, `sstamp` = SHA-256-prefix of the security stamp. A `JwtBearerEvents.OnTokenValidated` handler loads the user (cached ≤ 30 s) and rejects when inactive or the stamp hash differs. Refresh token = 32 random bytes base64url; stored SHA-256 hex hash only.
- Endpoints per API-SPEC §1: `POST /api/auth/login` (uses `IAuthService.AuthenticateAsync`; maps `LockedOut → 423`, `InvalidCredentials → 401` generic problem, `MustChangePassword → 403` problem `password-change-required`), `POST /api/auth/refresh`, `POST /api/auth/logout` (204; revokes supplied refresh token), `GET /api/auth/me`.
- Policy scheme `smart`: `Authorization: Bearer …` → JWT, otherwise cookie; `/api` challenge → 401 JSON, forbid → 403 JSON (never redirect).
