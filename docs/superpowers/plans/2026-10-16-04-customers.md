# Customer Management Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans if your harness has them; otherwise execute task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Customer CRUD with validation, duplicate prevention, scope, audit and a designed list/detail/form UI. It also lays the shared "module kit" every later module reuses.

**Architecture:** `Customer` entity + EF configuration + migration; `CustomerRules` in Domain; `ICustomerService` in Application (permission → scope → validation → persistence); MVC controller with ViewModels and Razor views; client-side validation attributes that mirror Domain rules.

**Tech Stack:** EF Core, DataAnnotations + custom attribute adapters, jQuery Validation Unobtrusive, Razor, xUnit, Playwright.

**Spec:** PRD CUST-01..07, VAL-01..06, D-03, D-10, D-12, D-13; DATA-MODEL §3 Customers, `UserSummary`; SECURITY-AUTHZ §3.

**Depends on:** Plans 01, 08A, 02, 03, 08B.

## Global Constraints
- Name ≤ 150, company ≤ 150, email ≤ 254, phone 10 normalised digits, address ≤ 300, city/state ≤ 100, notes ≤ 2000. Required: name, email, phone.
- Unique (non-deleted) email (case-insensitive) and phone; messages `A customer with this email already exists.` / `A customer with this phone number already exists.`
- SalesExecutive creating a customer always owns it; `OwnerId` from the request is ignored for them. Manager/Admin may set an owner who is active and in scope (AUTHZ-04).
- Customers are never hard-deleted. `DeleteAsync` = soft delete (D-10).
- Concurrency conflict message: `This customer was changed by someone else. Reload and try again.`
- Page size default 25.

## Review Focus
- Phone/email duplicate where the other record is soft-deleted → allowed (filtered index); where the other record is owned by a user outside the caller's scope → still rejected, but the message must **not** reveal that record's id/name/owner (only the generic duplicate message).
- Two simultaneous creates with the same email: exactly one succeeds, the other gets the duplicate message (not a 500).
- Email `Asha@Acme.IN` vs existing `asha@acme.in` → duplicate. Phone `+91 98765 43210` vs existing `9876543210` → duplicate.
- Editing a customer without changing email/phone does not trip the duplicate rule against itself.
- Search term containing `%`, `_`, `[` or SQL fragments (`' OR 1=1 --`) returns correct literal-match results and no error.
- Opening `/Customers/Details/{id}` of another team's customer → 404 (not 403, not an empty page).
- Whitespace-only name, trailing spaces in email, 151-char name, notes with 2001 chars.
- POST with `Status=99` or `OwnerId` of a deactivated user.
